BUG-001 / BUG-004 / BUG-005 — setState in effect body

Files: JourneyClient.jsx:38, GameIntro.jsx:14, mermaid-diagram.tsx:45

The setMounted(true) inside useEffect is a common SSR-gate pattern but React 19's strict ESLint rules flag it. Use useSyncExternalStore for hydration-safe mount detection, or suppress the lint rule for this specific idiom if the pattern is intentional.

// Option A: Replace with useSyncExternalStore (no cascading render)
import { useSyncExternalStore } from "react";

const subscribe = () => () => {};
const getSnapshot = () => true;
const getServerSnapshot = () => false;

function useIsMounted() {
  return useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot);
}

// Usage:
const mounted = useIsMounted();

BUG-002 — Ref mutation during render

File: JourneyClient.jsx:76

Move the ref sync into an effect so it doesn't run during the render phase:

// Before (renders body):
storyCompleteRef.current = storyComplete;

// After (effect):
useEffect(() => {
  storyCompleteRef.current = storyComplete;
}, [storyComplete]);

BUG-003 — Mutating hook return value

File: AutoFitOrtho.jsx:56

R3F's useThree returns an immutable camera reference. Use R3F's imperative handle or wrap in useFrame:

// Use useFrame's callback which provides the mutable state:
import { useFrame, useThree } from "@react-three/fiber";

useFrame(({ camera }) => {
  // camera here is the live mutable reference
  camera.zoom = zoom;
  camera.updateProjectionMatrix();
});

ARCH-007 — Dark mode custom-variant specificity

File: globals.css:38

- @custom-variant dark (&:is(.dark *));
+ @custom-variant dark (&:where(.dark, .dark *));

:where() has zero specificity, so dark-mode utility overrides work exactly like their light-mode counterparts. :is() picks up the specificity of its most specific argument, which can cause dark:bg-* to unexpectedly override non-dark utilities.
